# Buttons and camera: what the board actually needs

Both of these subsystems "did not work" for non-obvious reasons. This
document records the investigation and the fix so it doesn't get re-litigated.

## 1. Buttons (ADC ladder on GPIO42)

### Symptom

Every ADC1 conversion read `0`, in Rust *and* in ESP-IDF.

### What was ruled out

- The digital sequence is identical to IDF's `adc_oneshot_hal_convert()`.
- Conversions really complete: `APB_SARADC.int_raw.sar1_done` goes high.
- The regi2c bus works: writes to the SAR analog blocks (`0x10` = SAR1,
  `0x11` = SAR2) land and read back correctly. Enabling `EN_RAW_DATA`
  (block reg `0x4` bit 4) and `CAL_DONE` (reg `0x0` bit 0) — which the vendor
  BSP does — did not change the readings.
- Clock dividers, `sar1_clk_pos_sel`, and delays after the trigger made no
  difference.

### Decisive experiment

An IDF app built from the local `esp-idf` checkout
(`/home/nws/w/esp32/s31-idf-adc-probe`) reads the same channel through
`adc_oneshot_read()` and also gets `0`. So neither esp-hal nor the toolchain
was at fault.

### Root cause

The ladder is wired to **GPIO42 = `ADC1_CH0_N`**, the *negative* input of the
differential SAR channel (see the comment next to `BSP_BUTTONS_ADC` in
`esp32_s31_korvo.h`). The ladder idles at 2 V = the bottom of the code range,
so `0` is the correct idle reading — the mapping is inverted, not broken.

The vendor BSP encodes this in `bsp_s31_adc_calibration_raw_to_mv()`:

```c
mv = 2000 - (4000 * code_q) / (4393 * SCALE);
```

with `code_q` the weighted sum of the 17 SAR bits (weights sum to 4393):
`{2048, 1024, 512, 256, 256, 128, 64, 32, 32, 16, 8, 8, 4, 2, 2, 0, 1}`, MSB
first. `buttons.rs` ports both.

Result: idle = 2000 mV, and VOL+/VOL-/MODE/SET land on 380/820/1340/1870 mV,
the same thresholds the stock firmware uses.

### Local esp-hal change

`esp-hal` (`s31-adc-clock-patch` branch) now performs the vendor's regi2c
analog setup in `Adc::new`: `EN_RAW_DATA = 1` and `CAL_DONE = 1` on the unit's
SAR block. Added `regi2c_write_mask()` to `soc/esp32s31/regi2c.rs` for it.

## 2. DVP camera

### Symptom

No SCCB device answered; an I2C scan only showed 0x10 (codec) and 0x14
(touch).

### Bring-up (from the vendor example and `esp_driver_cam`)

| Step | Detail |
|---|---|
| XCLK | **20 MHz on GPIO55, generated by the DVP controller itself** (160 MHz PLL ÷ 8, integer divider). Not LEDC, not PWM — the per-sensor `*_ENABLE_OUT_XCLK` macros in the vendor driver are empty no-ops, which proves the clock must already be running. |
| Settling | 100 ms (`SC101IOT_XCLK_STABLE_TIME_MS`). OV3660 needs 20 ms. |
| PWDN / RESET | Both are `GPIO_NUM_NC` on this board — there is nothing to toggle, and no LDO enable GPIO exists either (the 2.8 V / 1.5 V camera rails follow board 3V3). |
| SCCB speed | 100 kHz is fine here; the vendor uses a very conservative 10 kHz. |

In Rust this is `Camera::new(cam, dma, Config::default().with_frequency(20 MHz))`
plus `with_master_clock(GPIO55)`.

### The second gotcha: paged SCCB

The SC101IOT does **not** take 16-bit register addresses. `sc101iot_read_a16v8`
writes the high byte into register `0xf0` and then accesses the 8-bit low byte:

```c
esp_sccb_transmit_reg_a8v8(sccb, 0xf0, reg >> 8);
esp_sccb_transmit_receive_reg_a8v8(sccb, reg & 0xff, &value);
```

With that, the board reports **SC101IOT, PID 0xda4a** (registers 0x31f7/0x31f8).
OV3660 (0x3c, plain 16-bit addressing) is not populated on this unit.

### Remaining work: live capture

1. Port the vendor init table — `sc101iot_dvp_8bit_20Minput_640x480_yuv422_uyvy_15fps.h`
   is ~190 `(reg, val)` entries, including `0xfe` = delay markers and the
   `0xf0` page switching.
2. Configure the DVP port: 8-bit bus, YUV422, HREF on `de_io` (not `hsync_io`),
   PCLK on GPIO54.
3. Receive with `Camera::receive()` into PSRAM and convert YUYV → RGB565 for
   the LCD.

Note: only `DMA_AXI_CH0` is wired to LCD_CAM on this chip, and its TX half
streams the LCD. `camera.rs` therefore hands the driver a second handle to the
same channel for its RX half; it is never used because no transfer is started.
